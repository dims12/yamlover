# `edit-examples/` — the edit-sequence corpus

Each fixture is a **sequence of keystrokes** replayed through the real projectional editor into a
real server, plus what the file must look like afterwards. Sibling of `test-examples/` (which pins
the parser and serializer); this corpus pins the **editor**.

It exists because the editor's other tests mock `api.ts`, so a server rejection —
`edit sync failed: …` — cannot reach them. Here the ops are real, the handler is real, the tree is
real, and a keystroke with nowhere to go fails the fixture at the keystroke that caused it.

Harness: `tools/server/test/edit-corpus.test.tsx` + `edit-corpus-harness.ts`.
Generator: `npm run gen:edit-fixtures` (in `tools/server`).

## A fixture

```
edit-examples/0042/
  ===            one-line title
  keys           THE EDIT SEQUENCE — the keystroke script
  in.yo    optional: the starting document (absent ⇒ an empty one)
  expect         `roundtrip` (default) | `bytes`
  out.yo   required for `expect: bytes` — the file, byte-exact
  from           generated fixtures only: the document the script was derived from
```

Ids follow `test-examples`: four digits, with `0003-01` sorting between `0003` and `0004` for
insertions. **`0001`–`0099` are hand-written; `0100`+ are generated** and are rewritten wholesale by
the generator, so never edit those by hand.

## The keystroke script

Literal text, plus named keys in braces:

```
world:{Enter}"australia and oceania":{Enter}australia: ~{Enter}{ShiftTab}oceania: ~{Blur}
```

`{Enter}` `{Tab}` `{ShiftTab}` `{Backspace}` `{Delete}` `{Escape}` `{Left}` `{Right}` `{Up}`
`{Down}` `{Blur}`, and `{{` for a literal `{`. A raw newline is an error — line breaks are
`{Enter}`, so a script cannot silently mean two things.

`{Blur}` is not a key: it marks the COMMIT BOUNDARY — how a person leaves the editor. Most
scripts end with it. The yed runners (the pure corpus in `tools/yed/test/corpus.test.ts` and the
server replay) map it to `{ArrowRight}`, yed's move-free commit: yed has no commit-on-blur, and
moving away commits (or refuses — nothing is ever lost).

## THE LEVEL RULE

Scripts must follow the editor's actual grammar (`YAMLOVER_EDITOR.yo`
§"THE LEVEL RULE"): **Enter after committing a value DESCENDS into it**, so a sibling costs one
`{ShiftTab}` and each step further out costs another. Writing a script as though Enter meant "next
sibling" produces a document three levels deep — the generator's arithmetic is exactly this rule.

## What a fixture asserts

**`roundtrip`** (every generated fixture): the file on disk must **reparse to the same IR** as its
`from` source — `canonDoc` equality, the identity `test-examples` uses. Self-validating: there is no
golden to bless, and it states the property that matters — *the editor recorded what I typed*. A
generated byte-golden would instead freeze today's bugs as the expectation. Comments and blank lines
are not part of IR identity, so a source may carry them.

**`bytes`**: `out.yo` compared byte-exact. For hand-written fixtures where the formatting IS
the behaviour — flow tokens, quote styles, block scalars, the `yaml/…` representation concretes.

## The substrate

A fixture types into a **standalone `.yo` file**, so it tests the typing grammar and nothing
else. In a directory-backed document the storage policy also applies (a keyed node that gains
container content is promoted into its own subdirectory), so content would leave the file
mid-sequence. Fixtures for that policy belong in the server suites, which can assert over the tree.

## The allowlist

Known-failing fixtures live in an `ALLOWLIST` in the harness, each with its cause. The gate is
honest in both directions: a non-listed fixture must pass, and a **listed one must still fail**, so
fixing a defect tells you exactly which ids to delete. It only shrinks — it is the editor's defect
inventory.

`SKIPPED.md` records the sources the generator could not turn into a sequence at all, grouped by
reason. Those are shapes a person cannot currently type; shrinking that list is a feature request.
